### Why Vite (motivation)

The Next.js 16 + OpenNext Cloudflare Worker bundle is ~3.5 MB gzip, over the 3 MB free-plan limit and growing. Vite + React Router v7 (SPA) removes the Next.js/OpenNext overhead (~1.5 MB gzip), leaving a static bundle well under 1 MB. The apps are login-gated and clinician-facing, so losing SSR has no SEO impact.

### Target architecture

```
Browser → Cloudflare Edge (Static Assets)
           ├── /assets/* → static files (immutable cache)
           ├── / → index.html (SPA fallback via public/_redirects)
           └── /api/* + /socket.io/* → Hono API proxy Worker (apps/app-vite/api/index.ts, < 100 KB gzip) → NestJS backend
```

- Security headers via static `public/_headers`; no CSP nonce needed (no inline scripts in an SPA).
- WebSocket/socket.io upgrades must be forwarded by the proxy Worker (upgrade handshake).
- Env vars: `VITE_*` prefix only (no `NEXT_PUBLIC_*` in new code).

## Porting mechanics (cheat sheet)

| Next.js pattern                                                                                          | Vite/React Router replacement                                                     |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `next/link` `<Link href="...">`                                                                          | `react-router` `<Link to="...">`                                                  |
| `useRouter().push(p)` / `.replace(p)`                                                                    | `useNavigate()(p)` / `useNavigate()(p, { replace: true })`                        |
| `usePathname()`                                                                                          | `useLocation().pathname`                                                          |
| `useSearchParams()` / `useParams()`                                                                      | Same names in `react-router`                                                      |
| `next/image`                                                                                             | `<img>` with explicit `width`/`height` + `loading="lazy"`                         |
| `dynamic(() => import(...), { ssr: false })`                                                             | `React.lazy` or React Router v7 route `lazy` property                             |
| `export const metadata` / `next/head`                                                                    | `react-helmet-async` `<Helmet>` (wrapped in `<HelmetProvider>` at root)           |
| `error.tsx` / `global-error.tsx` / `not-found.tsx`                                                       | Route `errorElement` / root `errorElement` / catch-all `*` route                  |
| `next-intl` (`useTranslations`, `NextIntlClientProvider`)                                                | `i18next` + `react-i18next` (initialized in `src/i18n/index.ts`)                  |
| `next-themes`                                                                                            | LocalStorage + CSS class theme store (already implemented)                        |
| `@sentry/nextjs`                                                                                         | `@sentry/react` (no server config — `sentry.server.config.ts` deleted)            |
| `export const dynamic = "force-dynamic"` / `"use client"`                                                | Remove — meaningless in an SPA (strip during porting)                             |
| `next/headers`, `next/server` (middleware), `instrumentation.ts`, `next-env.d.ts`, `open-next.config.ts` | Delete — replaced by proxy Worker + `_headers`/`_redirects` + `src/env.d.ts`      |
| Tests mocking `next/navigation` / `next/link`                                                            | Wrap in `<MemoryRouter initialEntries={["/"]}>`; never port no-op `vi.mock` stubs |
| Playwright web server                                                                                    | `vite dev` (not `next dev`), update port                                          |

Rules while porting:

- Port tests with the feature — never port no-op `vi.mock("next/link")` / `next-intl` stubs; they mask real import issues.
- Respect SSOT (AGENTS.md §15.12): no duplicated status-label maps, no removed tier symbols, no parallel hand-written types.
- Strip `"use client"` / `export const dynamic` directives from ported files.
- Follow the canonical feature split (AGENTS.md §15.5): `use-*.ts` hook + `*-sections.tsx` + `*-helpers.ts` + thin page shell.
- Apply the full dead-code and structure rules in the next section to every ported file.

## Porting standards: dead code, structure, reuse

These rules apply to every feature port. They operationalize AGENTS.md §7 (hygiene), §12 (SOLID/KISS/DRY), and §15 (patterns). The historical Next tree is a **menu, not a mandate** — port only what is live business and structure it properly. The current branch is Vite-only at the tracked tree level, so do not create a second frontend implementation to preserve parity mechanically.

### Do not port (dead code and unwanted items)

> Central removal inventory: [`docs/CODEBASE_CLEANUP_PLAN.md`](CODEBASE_CLEANUP_PLAN.md) classifies every deletion candidate (dead CI jobs, knip findings, port-or-drop items, cutover deletions) by when it can be removed.

- **Unreachable code**: before porting a file, confirm it is reachable from a route (directly or via a shared lib a route uses). Orphaned helpers, unused exports, and dead branches in the Next tree are **deleted, not ported**. When in doubt, inspect the historical Next tree from an explicitly selected Git revision (`git log --all -- apps/app/<feature>` followed by `git ls-tree <revision> apps/app --name-only`) and use `rg` to confirm importers.
- **Dead features**: routes with no confirmed live business (excel, ocr, guided-tour, dev-tools, feedback, specialty) go through the Phase 6 port-or-drop review; default is drop the route, not port it. **(Applied 2026-08-02 — see the Phase 6 decisions table.)**
- **Legacy symbols**: `workspaceProfile`, `isFrontDeskWorkspace`, removed `FRONT_DESK*` tier enum values, the 9-state invoice model, the 1-value `DiscountType` — never port (AGENTS.md §15.8 / §15.12). Enforced by `check:workspace-profile-gating`, `check:tier-comparisons`, `check:type-duplicates`.
- **Next-only runtime**: `next/navigation`, `next/headers`, `next/image`, `middleware.ts`, `instrumentation.ts`, `next-env.d.ts`, `open-next.config.ts`, `@sentry/nextjs` server config, `next-themes` — replaced per the cheat sheet above, never ported.
- **Parallel types**: never hand-write interfaces alongside Zod schemas — derive with `z.infer` from `packages/types` (AGENTS.md §3.1). If the Next file defines a shape that already exists in types, delete the local copy; if it does not exist, **add the schema to `packages/types` first**, then import it.
- **Duplicate UI**: resolve every component against the sourcing order below. App-local duplicates of `@workspace/ui` primitives (EmptyState, BackButton, dialogs, selects, toasts...) are deleted, not ported.
- **Dead tests and stubs**: no `vi.mock("next/link")` / `next-intl` no-op stubs, no tests asserting deleted behavior. Port the test with the feature or not at all (AGENTS.md §10, §15.10).
- **Placeholder stubs**: as a feature lands, delete its shell placeholder (e.g. the `Tabs placeholder` in `PatientDetailPage.tsx`, the `Mapping step placeholder` in `imports-page.tsx`). No TODO/FIXME survives the port — implement the behavior, then remove the note (AGENTS.md §7.2).
- **Comment baggage**: strip comments that restate code; keep only security/compliance/invariant "why" comments. No emojis, no `console.log` (use `@/lib/logger`).
- **Unused dependencies**: no dependency is added without a consumer in the ported code; `pnpm knip` + `pnpm check:hygiene` run at each phase gate.

### Structure ported files (SOLID + design patterns)

The Vite port is the moment to apply patterns, not to reproduce Next files 1:1. Every new/changed file follows the canonical splits (AGENTS.md §15.5) and the component sourcing order (AGENTS.md §4.3).

**Reuse before write (sourcing order — non-negotiable):**

1. `packages/types` (Zod schemas + `z.infer`) for every data shape — add missing schemas there first.
2. `packages/data-access` hooks (`useAppointments`, `usePatients`, ...) for server state — add per-domain hooks there.
3. `@workspace/ui` primitives for every UI need; `packages/hooks` for cross-app React hooks; `packages/utils` for pure helpers (validation, formatting, SSOT constants).
4. Existing `apps/<app>/src/{components,hooks,lib}` when at least two features share the behavior.
5. Only then: a new primitive in `packages/ui` (preferred) or a local file — documented in the PR with a one-line rationale.

**Canonical split per feature** (AGENTS.md §15.5): `use-<surface>.ts` (state + I/O + React Query) → `<surface>-sections.tsx` (presentational blocks; props in, events out; no fetch) → `*-helpers.ts` (pure functions; no React imports) → thin route page that only composes (`AppPageScaffold → PageHeader → DataState`). A 800-line Next page becomes four single-responsibility files; `pnpm check:file-size-budget` (400-line backstop, tests excluded) enforces the ceiling.

**SOLID per file:**

- Single responsibility — one reason to change per file; split mixed read/write orchestration per the §15.5 split table.
- Open/closed — extend via props, strategy registries, and new `@workspace/ui` variants; do not branch inside stable call sites.
- Liskov substitution — ported mock/fixture factories satisfy the same shape as real ones.
- Interface segregation — components receive only the props they render; no mega-props or blind spreads.
- Dependency inversion — features depend on `packages/data-access` hooks and domain types, never raw `fetch` or Prisma.

**Typing discipline**: no `any`; narrow boundary `unknown` with Zod `safeParse`; no unchecked casts or `@ts-expect-error` outside isolated, justified helpers (AGENTS.md §7.3). `pnpm check:as-cast-density` gates.

**Imports**: `@/...` and `@workspace/...` only — no parent-relative `../` (ESLint-banned); no new import cycles (`pnpm check:circular:enforce`, baseline 0).

**i18n**: reuse the existing en/hi keys (already at parity) — no key duplication; `pnpm check:i18n-translation-keys` gates.

**Accessibility and motion**: ported surfaces use `@workspace/ui` primitives (focus rings, roles, aria built in); no decorative motion (`animate-pulse` on chrome, skeleton `wave`, `animate-in fade-in slide-in-from-bottom-*`, `transition-all` — AGENTS.md §4.3); `pnpm audit:app` / `audit:internal` per phase.

### Per-feature port procedure

1. **Inventory**: use the feature parity matrix, `apps/app-vite/src/App.tsx`, and the historical Next tree from Git (`git log --all -- apps/app/<feature>` or an explicitly selected pre-cutover revision). Do not treat the deleted `apps/app` path at the current branch tip as a live source tree.
2. **Reachability**: drop files with no importers in the Next tree; record port-or-drop decisions in the PR.
3. **Reuse resolution**: types → `packages/types`; server-state hooks → `packages/data-access`; UI → `@workspace/ui`; helpers → `packages/utils`; shared app code → `src/{components,hooks,lib}`.
4. **Restructure**: apply the canonical split; split files over 400 lines; strip Next-isms and legacy symbols.
5. **Port tests** (unit + component) with the feature; add E2E for critical journeys in the same phase (no test-debt deferral).
6. **Gate**: the feature's `check-feature-test-density` entry green; `lint` / `check-types` / `test` for the app; `pnpm knip` + `pnpm check:hygiene` at phase end.

### Porting completion contract

Every retained feature must have one explicit state and one evidence record. A feature is not `COMPLETE` because its route renders; it is `COMPLETE` only when its behavior, boundaries, tests, and release evidence agree.

| State        | Meaning                                                                                                                   | Required next action                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `COMPLETE`   | Route, real data path, access behavior, states, tests, and documentation are verified.                                   | Keep in the release set; re-run the route smoke after cutover/rename.                                    |
| `SHELL`      | Route/chrome exists, but a required API mutation, state, or integration is still missing.                                | Block release; name the missing contract and owner.                                                       |
| `DROP`       | Product confirmed that the legacy capability is not live business or is replaced by another workflow.                   | Remove route/CTA/import/test dependencies and record the decision.                                        |
| `DEFER`      | Product wants the capability later, but it is outside this cutover.                                                      | Keep it out of the release set; add a future requirement with an owner and trigger.                       |
| `BLOCKED`    | Implementation may be present, but external evidence cannot be collected (credentials, seeded DB, provider, or staging). | Name the prerequisite; do not convert the status to green through a skip or allowlist.                    |

For each `COMPLETE` or release-critical `SHELL` entry, attach a compact record containing:

- feature and route(s), personas/roles, and direct-URL behavior;
- API/data-access client and shared Zod request/response schemas;
- loading, empty, error, retry, offline, and destructive-action behavior;
- tenant/RBAC/audit/PHI considerations and existing-user compatibility;
- unit/component test files, E2E spec and fixture identity, and the exact command run;
- accessibility/performance/security evidence, known exception expiry, and the responsible owner.

The record belongs in the release PR or its linked evidence index. A skipped test, mocked API, or route-discovery result can prove structure, but cannot prove a `COMPLETE` runtime flow.

### Cutover and release runbook

Treat cutover as a release transaction with a known-good predecessor, a reversible deployment, and evidence captured at each boundary.

| Stage | Actions | Stop condition / evidence |
| ----- | ------- | ------------------------- |
| Preflight | Confirm branch is from current `main`; freeze unrelated frontend changes; record current production commit, migrations, environment names, provider versions, and rollback target. | Missing rollback target, migration order, or owner stops the release. |
| Repository cutover | Verify Vite paths are tracked, legacy Next paths are absent from the current tree, package names/scripts/filters are consistent, and canonical rename/reference sweep is complete. | `git ls-files`, reference audit, `verify:standard`, `knip`, circular check, lint, and typechecks are attached. |
| Contract gate | Run the authenticated route/persona matrix with seeded identities; exercise denied access, refresh, direct URL, timezone, upload, payment, webhook, and audit paths. | Any critical flow skipped, mocked-only, or credential-blocked remains `BLOCKED`; do not promote. |
| Artifact gate | Build both Cloudflare targets; inspect the exact deploy artifacts for old app paths, cross-origin telemetry, secrets, stale API URLs, missing headers, and broken Worker proxy routes. | Artifact search and header verifier must pass on the produced artifact, not only on source files. |
| Staging release | Deploy to staging, run browser smoke plus API/worker health checks, exercise PWA/offline and Razorpay paths, observe Sentry/telemetry, and complete the agreed soak window. | Staging smoke, alert ownership, and rollback rehearsal must be recorded before production. |
| Production release | Promote the same verified commit/artifact; run the smallest safe smoke set first, then the authenticated critical routes; monitor API, worker, queue, cache, error rate, and support signals. | Any tenant, auth, payment, data-integrity, or PHI-safety regression triggers rollback. |
| Closeout | Link release evidence, migration status, support notes, dashboard/alert ownership, staging parity, and branch cleanup. | Release is not closed until evidence is reproducible and the remote branch cap is respected. |

Rollback must be explicit: identify whether the failure requires artifact rollback, traffic rollback, feature-flag disablement, or database forward-fix. Never roll back application code across an irreversible migration without the migration-specific recovery procedure.

## Cutover checklist — definition of done for the Vite release

1. All P0/P1 routes functional with real API calls (no stubs, no placeholder comments).
2. P0/P1 features pass `check-feature-test-density` with unit tests; 100% of critical flows have tests.
3. E2E suite green in CI: auth, today/dashboard, consultation, appointments, patients, billing, subscription, portal, internal.
4. `pnpm verify:standard`, `pnpm knip`, `pnpm check:circular:enforce`, `pnpm lint`, per-package `check-types` pass with Vite apps as the only frontend apps — and no ported dead code (unreachable files, duplicate primitives, parallel types) survived the migration per the [Porting standards](#porting-standards-dead-code-structure-reuse) section.
5. PWA (SW registration), security headers, Sentry/PHI parity verified; `build:cloudflare:production` artifact search clean.
6. `AGENTS.md` + docs updated to the Vite layout — AGENTS.md, live docs, ADR 0012, app READMEs **done 2026-07-31**; historical pattern docs audited and retained only as context; `PAGES_AND_FEATURES.md` **regenerated 2026-08-02** (Vite route/feature inventory: 95 app-vite routes + 19 internal-vite routes mapped to features, port-status reference, verification state; product-roadmap parts archived to `FUTURE_FEATURE_REQUIREMENTS.md`); executable-reference sweep clean (only intentional historical records may retain legacy path text).
7. `deploy:cloudflare:production` smoke-tested for both apps (staging first, then production).
8. Existing-user compatibility reviewed (AGENTS.md §9.4): session carryover and onboarding-reset protection pass; subscription lockout, doctor verification, and denied direct-URL behavior have explicit product decisions and regression tests.
9. Authenticated route matrix passes with seeded clinician, front-desk, admin, patient-portal, and lab-portal identities; no critical flow is skipped and called green.
10. Full accessibility/performance/security evidence is attached: authenticated axe baseline, route/Worker budgets, PHI/tenant/RBAC/RLS/audit checks, headers/CSP, secret/artifact search, and same-origin telemetry.
11. Rollback and operations are rehearsed: migration ordering, health checks, queue/cache recovery, Sentry event, support escalation, release evidence, staging soak, and branch cleanup.
