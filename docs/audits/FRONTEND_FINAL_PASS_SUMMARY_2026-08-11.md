## What was NOT changed in code (and why)

This was a "document them as well" pass, not a refactor pass. The
asymmetry comes from the size of the codebase: 1,500+ frontend files,
171 useEffects, 94 dead exports, 28 contract files, 89 controllers,
~90 shared UI primitives. Refactoring any one of those surfaces
touches dozens of files and warrants its own dedicated PR with proper
review and tests. The right move is to give future agents the
inventory they need, not to ship a half-done refactor in a single
commit.

Specifically, the **14 `apps/internal` pages** that use the
`useState` + `useEffect(() => fetchData(), [])` mount-fetch pattern
are the single highest-value refactor target (~20 useEffects gone,
~300 lines of `try/catch`/`finally` noise removed, mutation wiring
standardized). The playbook for that refactor is in
`FRONTEND_BEST_PRACTICES_2026-08-11.md` §3 with a per-page template.
But the actual refactor is a 4-hour focused PR with per-page
behavior verification — not a single-pass cleanup.

## How to use these documents

1. **Starting a new feature?** Read `FRONTEND_BEST_PRACTICES_2026-08-11.md`
   §1 ("Existing shared primitives") first. Use them; don't reinvent.

2. **Adding a new endpoint?** Read `FRONTEND_BEST_PRACTICES_2026-08-11.md`
   §4.5 ("0 waste checklist") and follow the 6-step procedure.

3. **Debugging a stale-deps lint warning?** Look up the file:line in
   `FRONTEND_USEEFFECT_INDEX_FULL_2026-08-11.md` to see the full
   effect body, deps, and rationale for why it's there.

4. **Deleting a feature?** Cross-check against
   `FRONTEND_DEAD_CODE_FULL_2026-08-11.md` to see if any orphans
   should be cleaned up at the same time.

5. **Responding to a knip warning?** Search the relevant contract
   file in `packages/types/src/contracts/` to confirm the export is
   truly dead or if a barrel/index re-export needs updating.
