## Failures and repair

- [CI run 37047102935](https://github.com/CVamsi27/docita/actions/runs/37047102935):
  the PR scanner reported no new issues, then failed uploading SARIF because
  code scanning is unavailable on this private repository. The full scanner
  additionally failed on advisories already present in the base dependency tree.
- PRs now run the mandatory comparison scan; manual CI runs retain the
  mandatory full scan. Both explicitly keep `fail-on-vuln: true`. No vulnerability
  ignores, scanner error suppression or dependency changes are introduced.
- Both scanner calls use v2.6.0, matching the updates already merged into main.
  This version also rejects scans that fail without producing results.
- SARIF remains an Actions artifact. Security-tab upload requires repository
  variable `OSV_UPLOAD_SARIF=true` after code scanning is enabled; it defaults off
  while that service is unavailable.
- Two regression tests exercise actual workflow expressions across PR, push,
  manual, draft and unrelated-change contexts, plus upload opt-in and mandatory
  vulnerability failure settings. Both failed before the repair and passed after.

Local validation passed: full lint, Knip, the complete repository standards gate
including 49 standards tests on this PR branch, and actionlint v1.7.12 for the changed CI workflow.
The standards gate retains its existing informational skip for the absent staging
API-latency baseline. No application runtime or dependency manifest changed.

Main's two scanner-version updates conflicted with the repaired workflow, which
prevented GitHub from starting pull-request checks. They were merged into this
branch with both v2.6.0 calls and the new mandatory scan/reporting configuration
preserved. No application files required conflict resolution.

## Deployment configuration remains required

[Deployment run 37047095438](https://github.com/CVamsi27/docita/actions/runs/37047095438)
failed Cloudflare token verification with HTTP 401/code 1000, and the API startup
job lacked `TURNSTILE_SECRET_KEY`. Repository secret metadata confirms Turnstile
is absent; the local Cloudflare token also fails the existing verifier. The local
Turnstile secret returns `invalid-input-secret` for a synthetic verification.
None of these credential values were printed or copied into source.

Replace `CLOUDFLARE_API_TOKEN` following RB-13 in
[`RUNBOOKS.md`](../operations/RUNBOOKS.md), and set `TURNSTILE_SECRET_KEY` from the
production widget in repository secrets. Deployment checks remain blocking until
valid credentials are configured. This repair does not change production startup,
bot protection, deployment triggers, migrations or historical outbox delivery.
