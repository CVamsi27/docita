## Deployment configuration remains required

[Deployment run 37047095438](https://github.com/CVamsi27/docita/actions/runs/37047095438)
failed Cloudflare token verification with HTTP 401/code 1000, and the API startup
job lacked `TURNSTILE_SECRET_KEY`. Repository secret metadata confirms Turnstile
is absent; the local Cloudflare token also fails the existing verifier. The local
Turnstile secret returns `invalid-input-secret` for a synthetic verification.
None of these credential values were printed or copied into source.

Replace `CLOUDFLARE_API_TOKEN` following RB-13 in
[`RUNBOOKS.md`](../operations/RUNBOOKS.md), and set `TURNSTILE_SECRET_KEY` from the
production widget in repository secrets. Deployment checks remain blocking until
valid credentials are configured. This repair does not change production startup,
bot protection, deployment triggers, migrations or historical outbox delivery.

The public widget sitekey is supplied through repository variable
`VITE_TURNSTILE_SITE_KEY` to the app's CI build and production build/deploy step.
Vite embeds it in the browser bundle at build time; a Worker runtime binding does
not configure an already-built SPA. The app env template and Turbo environment
allowlist already declare this variable. Internal login redirects to the main app,
so the current internal portal does not need a separate widget build setting.
The matching private secret remains required in GitHub and the API runtime.

The user subsequently updated both GitHub credential secrets; their presence and
update times were verified from metadata without reading or printing values. The
provided public sitekey was saved in the repository variable and confirmed in the
production auth and public-booking bundles. Production app build, Worker dry-run,
deployment contracts, workflow references and hygiene passed. This wiring does
not write the API's runtime secret or claim the new widget is deployed live.

## Branch release window closure and workflow pause

Deployments from feature branches are disabled. The branch had an active push trigger
in `deploy.yml` (`branches: [main, fix/actual-operational-metrics]`) that ran production
deploy steps on push. The Fly.io token is unauthorized and the Cloudflare token lacked
scope for the configured account, causing failed commit checks on PR #319 despite all
10 CI jobs and E2E suites passing.

To match the repository-wide paused deployment contract (and PR #320), both `deploy.yml`
and `db-migrations.yml` now configure valid push triggers that ignore all branches and
tags (`branches-ignore: ["**"]`). The Cloudflare credential gate in `deploy.yml` restores
the non-failing exit-0 warning behavior when credentials are unavailable or invalid.
Deployment contracts, workflow script references, standards tests, and repository
hygiene remain fully verified.
