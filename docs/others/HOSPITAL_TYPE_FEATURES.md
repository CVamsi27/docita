## Detailed Clinic Type Specifications

### 1. GENERAL - General Medicine

**Description:** Full-featured general practice with all consultation features enabled. Suitable for family medicine, internal medicine, and general practitioners.

**Recommended Appointment Duration:** 15 minutes

**Enabled Features:**

- Chief Complaint
- History (Complete medical history)
- Examination (Physical examination)
- Vitals (BP, HR, Temp, SpO2, etc.)
- Diagnosis (ICD-10 coding)
- Treatment (Treatment plans)
- Investigations (Lab orders, imaging)
- Prescriptions (Medications)
- Procedures (Minor procedures)
- Follow Up (Scheduling and notes)

**Workflow Characteristics:**

- Multi-visit tracking enabled
- Allows minor procedures
- No specialty-specific requirements
- Suitable for all general medical conditions

**Ideal For:**

- Family medicine practices
- Internal medicine
- General practitioners
- Walk-in clinics

### 2. DENTAL - Dental Clinic

**Description:** Streamlined dental workflow with tooth charting. Optimized for oral health, dental procedures, and treatment planning.

**Recommended Appointment Duration:** 30 minutes

**Enabled Features:**

- Chief Complaint

- Diagnosis
- Treatment
- Investigations (X-rays, OPG, CBCT)
- Prescriptions (Antibiotics, pain management)
- Procedures (Fillings, extractions, RCT)
- Follow Up
- **Dental Chart** (Interactive tooth charting)

**Special Features:**

- **Dental Chart:** Visual tooth-by-tooth documentation
- Simplified workflow without detailed medical history
- Optimized for quick dental consultations
- Multi-visit tracking for complex procedures (RCT, orthodontics)

**Workflow Characteristics:**

- Specialty notes required for dental procedures
- Allows minor to moderate dental procedures
- Multi-visit tracking for orthodontics and root canals
- Focus on oral cavity examination

**Ideal For:**

- General dentistry
- Dental surgeons
- Orthodontists
- Oral health clinics

**Common Procedures:**

- Fillings and restorations
- Root canal therapy (RCT)
- Extractions
- Scaling and polishing
- Crown and bridge work

## Appointment View - Doctor Selection

### For Receptionist, Admin, and Admin_Doctor Roles

When viewing the appointments calendar, users with administrative privileges (Receptionist, Admin, Admin_Doctor) can:

1. **View All Doctors' Appointments:** See a unified calendar with appointments from all doctors in the clinic
2. **Filter by Specific Doctor:** Use a dropdown to select and view a specific doctor's schedule
3. **Create Appointments for Any Doctor:** Book appointments on behalf of any doctor in the clinic

**Doctor Selection Dropdown:**

- Located at the top of the appointments page
- Shows all users with DOCTOR or ADMIN_DOCTOR roles
- Default: "All Doctors" (shows combined calendar)
- Updates the calendar view in real-time when changed

**Example Workflow:**

```
1. Receptionist logs in
2. Navigates to Appointments page
3. Sees dropdown: "View Doctor's Calendar"
4. Selects "Dr. John Smith" from dropdown
5. Calendar updates to show only Dr. Smith's appointments
6. Can create new appointment for Dr. Smith
7. Can switch to another doctor or "All Doctors" view
```

### For Doctor Role (Regular Doctors)

Doctors only see their own appointments and cannot view other doctors' schedules. The dropdown is not shown for regular doctor users.

## Configuration Guide

### Setting Clinic Type During Creation

When creating a new clinic in the Super Admin dashboard:

1. Navigate to **Super Admin Dashboard**
2. Click **"Create Clinic"**
3. Fill in required details:
   - Clinic Name
   - Email
   - Phone
   - Address
4. Select **Tier** (CAPTURE, CORE, PLUS, PRO, ENTERPRISE)
5. **Select Clinic Type** from dropdown:
   - Choose the specialty that best matches the clinic
   - Default: GENERAL
6. Toggle **Intelligence addon** if needed
7. Click **"Create Clinic"**

### Changing Clinic Type

To change an existing clinic's type:

1. Navigate to **Super Admin Dashboard**
2. Find the clinic in the list
3. Click **"Edit"** button
4. Change **"Clinic Type"** dropdown
5. Click **"Update Clinic"**
6. Changes take effect immediately

### Effects of Changing Clinic Type

When you change a clinic's type:

- Consultation interface updates immediately
- Relevant tabs show/hide based on new type
- Specialty features activate/deactivate
- Existing data remains intact
- No data loss occurs
- ️ Some tabs may become hidden (but data is preserved)

## Best Practices

### Choosing the Right Clinic Type

1. **Match Your Primary Specialty:** Select the type that best represents your main medical specialty
2. **Consider Workflow:** Choose a type that streamlines your most common consultation patterns
3. **Feature Requirements:** Ensure the type includes all features you need regularly
4. **Use SPECIALTY for Flexibility:** If your practice doesn't fit a specific category, use SPECIALTY type

### Customization Tips

1. **Start with a Standard Type:** Begin with the closest matching type
2. **Review Feature Set:** Check if all required features are enabled
3. **Test Workflow:** Complete a few consultations to ensure the workflow fits
4. **Adjust if Needed:** Change type if the initial selection doesn't work well

### Multi-Specialty Clinics

For clinics offering multiple specialties:

- Use **SPECIALTY** type for flexibility
- Consider separate clinic profiles for each specialty
- Use doctor specialization fields to differentiate

## Technical Implementation

### Type Configuration Location

- **Schema:** `packages/db/prisma/schema.prisma`
- **Types:** `packages/types/src/index.ts`
- **Features Matrix:** `packages/types/src/index.ts` - `CLINIC_TYPE_FEATURES`

### Accessing Clinic Type in Code

```typescript
import { CLINIC_TYPE_FEATURES, ClinicType } from "@workspace/types";

// Get features for a clinic type
const features = CLINIC_TYPE_FEATURES[clinicType];

// Check if a specific feature is enabled
if (features.dentalChart) {
  // Show dental chart component
}

// Get recommended duration
const duration = features.recommendedDuration || 20;
```

### Conditional Feature Rendering

The consultation component automatically shows/hides tabs based on the clinic's type:

```typescript
const features = useMemo(() => {
  const typeKey = (clinicType?.toUpperCase() || "GENERAL") as ClinicType;
  return CLINIC_TYPE_FEATURES[typeKey] || CLINIC_TYPE_FEATURES.GENERAL;
}, [clinicType]);

// Use features to conditionally render
{features.dentalChart && <DentalChartComponent />}
{features.growthChart && <GrowthChartComponent />}
```
