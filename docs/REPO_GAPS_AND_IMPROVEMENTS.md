## Cross-cutting release standard

An audit item is closed only when the implementation, its enforcement gate, and its runtime evidence agree. Local static checks are insufficient for flows that depend on Postgres, seeded roles, Cloudflare, secrets, queues, payments, or external providers.

The remaining release work is grouped into five evidence tracks:

| Track                   | Required evidence                                                                                                                           | Current state                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Real API behavior       | Seeded clinician/front-desk/admin/portal identities; real 401/403/404/409/429/5xx, timezone, upload, PDF, payment, webhook, and audit flows | **BLOCKED** on authenticated staging/CI fixtures                                             |
| Existing-user safety    | Subscription lockout, doctor verification, direct URL access, session carryover, onboarding reset protection                                | Carryover protection passes; three guard behaviors need product decisions and regression E2E |
| Security/privacy        | Dependency audit, tenant/RBAC, RLS, PHI encryption/redaction/read audit, headers/CSP, secrets, signed URLs, webhook replay protection       | Static gates largely green; Cloudflare secret/artifact and full runtime evidence remain      |
| Reliability/performance | API startup, queue/cache heartbeat, Sentry event, route/Worker budgets, PWA/offline behavior, rollback rehearsal                            | Local budgets/builds pass; staging soak and rollback evidence remain                         |
| Governance              | Branch cap, release evidence index, migration order, rollback/runbook, staging mirrors `main`                                               | Must be completed in the cutover/release PR                                                  |

Do not convert a **BLOCKED** item to **DONE** by adding an allowlist or skipping a test. Name the missing external prerequisite and carry it to the release checklist.

### Action-state protocol

- `OPEN → READY` requires an implementation or decision that is reviewable in the repository; a plan or an allowlist is not implementation.
- `READY → DONE` requires the exact closure evidence, environment, commit, and timestamp. “Passed locally” cannot close a staging/provider-dependent row.
- `BLOCKED` must name the missing prerequisite and the person/team who can provide it. If the prerequisite is unavailable for the release window, the row remains blocked and the release decision records the risk.
- Exceptions require an owner, rationale, compensating control, and expiry date. Expired exceptions return to `OPEN`; they do not become permanent baselines.
