# Suppression Ledger

Point-in-time: **2026-08-05**. Single source of truth for every static-analysis
suppression in the repo. Every entry is a deliberate trade-off: a check that
would otherwise fail has been told to ignore a specific file, line, or path.
Suppressions are the most fragile part of the gate suite because they are
invisible to `git diff` and easy to accumulate without anyone noticing.

> **Rule of thumb.** A suppression is debt. Every entry must have a one-line
> rationale, an owner, and a target close date. Entries older than 90 days
> without progress are automatically re-promoted to a `P?` item in
> [`EXECUTION_PLAN.md`](EXECUTION_PLAN.md).

This doc is generated by hand from the source. Refresh procedure:

```bash
# 1. as-cast-density: every file with `check-as-cast-density: allow-file`
grep -rE "check-as-cast-density: allow-file" \
  apps packages --include="*.ts" --include="*.tsx" 2>/dev/null \
  | grep -v node_modules | grep -v "/dist/" > .suppression-as-cast.txt

# 2. non-null-assertion
grep -rE "check-non-null-assertion: allow-file" \
  apps packages --include="*.ts" --include="*.tsx" 2>/dev/null \
  | grep -v node_modules | grep -v "/dist/" > .suppression-nna.txt

# 3. jscpd .jscpd.json ignore entries
node -e "console.log(require('./.jscpd.json').ignore.length)" \
  > .suppression-jscpd-count.txt

# 4. eslint-disable in source (excluding node_modules)
grep -rE "eslint-disable(-next-line)?" \
  apps packages --include="*.ts" --include="*.tsx" 2>/dev/null \
  | grep -v node_modules | grep -v "/dist/" > .suppression-eslint.txt

# 5. Allowlists under scripts/checks/allowlists/
ls -la scripts/checks/allowlists/
```

## 7. New entry policy (mandatory)

When adding a suppression, follow the [Ponytail](https://en.wikipedia.org/wiki/You_aren%27t_gonna_need_it)
discipline — ask first:

1. **Is the cast real, or can the type be expressed?** Try `satisfies`, `as
   const`, generic narrowing, or a typed helper first. Most casts are removable.
2. **If the cast is real, can the surface area be narrowed to one file?** A
   per-file `allow-file` marker is preferred over a project-wide allowlist.
3. **Add the marker with a one-line rationale.** Vague rationales
   ("type narrowing", "generic helper") are rejected at review.
4. **Add the entry to this ledger.** New suppressions discovered in review
   block the PR.

The companion gate `scripts/checks/check-as-cast-density.mjs` validates the
marker exists and is non-empty. Suppressions without a marker fail the gate.
